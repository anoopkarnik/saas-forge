The web app reads `apps/web/.env`, then `apps/web/.env.local` over it; shell and host variables win over both. The Prisma CLI reads `packages/database/.env`. `apps/web/.env.example` is the source of truth for names. Use [`pnpm doctor`](/landing/doc/setup-doctor) to fill them.

## Validation at boot

`apps/web/instrumentation.ts` validates the environment when a Node.js server process starts (`apps/web/lib/env.ts`). In production any issue stops the server; in development it only warns.

- `NEXT_PUBLIC_URL` must be an `http(s)` URL and `DATABASE_URL` a `postgresql://` URL.
- `BETTER_AUTH_SECRET` must be at least 32 characters and not a placeholder from an example file. The same applies to `BACKEND_HMAC_SECRET` once `BACKEND_URL` is set.
- `NEXT_PUBLIC_AUTH_EMAIL=true` requires `NEXT_PUBLIC_EMAIL_CLIENT` (sign-up sends a verification email).
- Each enabled integration requires its credentials (table below).
- Any non-empty `NEXT_PUBLIC_*` variable whose name looks like a secret (`SECRET`, `TOKEN`, `PASSWORD`, `PRIVATE`, `API_KEY`, `WEBHOOK_KEY`, `JWT_KEY`) is rejected, because `NEXT_PUBLIC_` values are inlined into the browser bundle.

## Adding a variable

1. Add it to the right `.env.example` in the same change.
2. If an integration toggle now needs it, add it to `INTEGRATION_REQUIREMENTS` in `apps/web/lib/env.ts`.
3. Give it a `HINTS` entry in `scripts/doctor.mjs`.
4. Never prefix a secret with `NEXT_PUBLIC_`, `VITE_` or `EXPO_PUBLIC_`: those are shipped to clients.
