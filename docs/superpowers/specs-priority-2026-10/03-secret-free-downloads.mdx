# 03 — Secret-Free Downloads

_Rank 3 · Track: engine trust · Effort: M · Narrows April #03 (security hardening)_

## Context

The programmatic path (`apps/web/lib/scaffold/service.ts`, `/api/v1/projects/*`) already follows the rule **"never collect secrets"**: it ships `.env.example` plus a generated `SETUP.md` (`lib/scaffold/setup-guide.ts`).

The interactive path does not. `POST /api/scaffold` accepts `body.envVars`, including `DATABASE_URL`, provider secrets and auth secrets typed into the wizard's `EnvField`s. It writes them into `apps/web/.env`, `apps/mobile/.env`, `apps/desktop/.env` and `packages/database/.env` inside the zip. Those secrets transit the platform's server, request logs, error trackers and any proxy.

## Why This Priority

For a product sold to developers, "we never see your keys" is a selling point, and the opposite is a liability that one log line can turn into an incident. It also unifies two divergent code paths (session download vs API download) into one builder, which #4 and #8 depend on.

## Overview

The server only ever receives **non-secret selections**. Secrets are either injected **client-side** into the downloaded archive, or filled in locally after download by the setup doctor (#9).

## Main Approach

- Classify every wizard field as `public` or `secret` using the existing `apps/web/lib/scaffold/secret-keys.ts`. The server rejects any request containing a `secret` key (`400 secret_not_accepted`).
- The server builds the archive with `.env` files containing only public toggles, plus `SETUP.md`.
- **Optional client-side injection.** If the user typed secrets into the wizard, the browser adds them to the downloaded zip locally: fetch the zip as a stream, append `.env.local` files with a streaming zip writer (for example `client-zip`) in the browser, then save. Nothing leaves the device.
- Otherwise, the zip includes a `.env.secrets.template` that `pnpm doctor` (#9) fills interactively.
- Merge `/api/scaffold` onto `lib/scaffold/service.ts` so both paths share one builder, one ledger write (`ScaffoldJob`) and one pricing call.
- Add a log-redaction rule in `packages/observability` for any `envVars` key as defence in depth.

## Deliverables

1. Field classification exported from `secret-keys.ts` and shared with the wizard UI (lock icon plus "stays on your device" hint).
2. Server rejection of secret keys, with a regression test.
3. Browser-side zip augmentation helper in `packages/ui/src/lib/` (root-only slot).
4. `/api/scaffold` refactored onto the shared scaffold service.
5. Logger redaction for env-like payloads.
6. A privacy note in landing docs: "Your keys never reach our servers."

## Likely Files / Systems Affected

- `apps/web/app/api/scaffold/route.ts`, `apps/web/lib/scaffold/service.ts`, `apps/web/lib/scaffold/secret-keys.ts`
- `packages/ui/src/blocks/dashboard/DashboardPage.tsx`, `packages/ui/src/components/home/EnvField.tsx`
- `apps/mobile/components/downloads/*` (mobile can only use the doctor flow)
- `packages/observability/src/*`

## Risks / Dependencies

- Browser zip re-writing must stream, because starters are tens of MB. Fall back to the doctor flow when the browser lacks streams support.
- Mobile cannot easily rewrite zips. It uses the `SETUP.md` / doctor flow only.
- Desktop downloads go through the same API, so they get the same behaviour for free.

## Verification

1. Server logs and request bodies for a download contain no `secret`-classified keys (test with a canary value).
2. A zip downloaded with secrets typed in the wizard contains them, and the network log shows they were never sent.
3. The session and API download paths produce byte-identical archives for the same selection.
4. A direct request to `/api/scaffold` containing `DATABASE_URL` is rejected with `400`.
