Use Notion as the CMS when your team already writes there. Set `NEXT_PUBLIC_CMS="notion"`.

## 1. Create the databases

Create eight databases in one Notion workspace: a main landing page database and one per section. The properties each one needs are listed in [Notion Database Schema](/landing/doc/database-schema).

Add one row to the landing page database whose **title** contains your `NEXT_PUBLIC_SAAS_NAME`. Section rows link to that row through a relation.

## 2. Create an integration

1. Open [Notion integrations](https://www.notion.so/profile/integrations) and click **New integration**.
2. Name it (for example "Acme CMS") and choose the workspace.
3. Under **Capabilities**, enable **Read content**. Enable **Update content** and **Insert content** too if you want to edit the landing page from the admin panel.
4. Copy the **Internal Integration Secret**.
5. On each of the eight databases, open **⋯ → Connections** and add the integration.

## 3. Configure the environment

```env
NEXT_PUBLIC_CMS="notion"
NOTION_API_TOKEN="ntn_..."
LANDING_DATABASE_ID="..."
HERO_DATABASE_ID="..."
FEATURE_DATABASE_ID="..."
TESTIMONIAL_DATABASE_ID="..."
PRICING_DATABASE_ID="..."
FAQ_DATABASE_ID="..."
FOOTER_DATABASE_ID="..."
DOCUMENTATION_DATABASE_ID="..."
```

A database ID is the 32-character string in the database URL: `https://www.notion.so/<workspace>/<DATABASE_ID>?v=…`.

`pnpm doctor` checks `NOTION_API_TOKEN` with a live call. Production refuses to start without it when the CMS is `notion`.

## Images

Notion serves uploaded files from signed S3 URLs that expire after about an hour. `prod-files-secure.s3.us-west-2.amazonaws.com` is already allowed in `images.remotePatterns`, and the landing content is cached for an hour, so links refresh with the cache. For logos and large images, prefer hosting the file yourself and pasting its URL.

## Documentation in Notion

Each row of the documentation database is a page. Its title becomes the doc title, the slug is the title in lowercase with spaces replaced by dashes, and the page body is rendered block by block. Rows are ordered by the `order` property and grouped by `Type`.

The docs editor in the admin panel works with the Postgres CMS only. With Notion, edit docs in Notion.
