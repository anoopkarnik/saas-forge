The AI Agents & RAG module (`ai_agents`, requires AI Platform and Jobs) adds a Python service in `apps/backend` for work that does not fit a request: multi-step LangGraph agents, background jobs, and retrieval-augmented generation over your documents.

## Architecture

The web app authenticates the user, checks credits and validates input. Streaming requests call the Python execution API with an HMAC-SHA256 signature; background agent runs and ingestion are orchestrated by **web Inngest functions**. Python exposes signed execution endpoints rather than running a separate queue worker.

`apps/web/lib/ai-jobs/functions.ts` registers agent execution, document ingestion and recovery of pending jobs. Progress is stored in `AiJobRun` and `AiJobEvent`. Keep the backend reachable only through a controlled deployment path, with the HMAC secret shared by web and backend.

## Local setup

```bash
# Postgres with pgvector
docker compose up -d postgres

# Python dependencies (needs Python 3.12+ and uv)
pnpm --filter @workspace/backend build      # uv sync --frozen

# Backend env
cp apps/backend/.env.example apps/backend/.env
```

Then:

- set the same `BACKEND_HMAC_SECRET` in `apps/web/.env` and `apps/backend/.env` (`pnpm doctor` generates it and writes both);
- set `BACKEND_URL=http://localhost:8403` in `apps/web/.env`;
- set `BACKEND_DATABASE_URL` (a `postgresql+asyncpg://` URL to the same database) in `apps/backend/.env`;
- add a provider key such as `OPENAI_API_KEY` to `apps/backend/.env` for LLM calls and embeddings.

Run it:

```bash
pnpm --filter @workspace/backend dev              # API on :8403
curl http://localhost:8403/healthz
```

Configure and run Inngest against the web app’s `/api/inngest` route for background execution. Set the credentials listed in `apps/web/.env.example`; the Python service does not need a Redis job queue. The container listens on port 8000, so set `BACKEND_URL` for your deployment rather than copying the local development port.

## Agents

Built-in agents, registered in `apps/backend/src/saas_forge_backend/agents/registry.py`:

| Agent ID    | What it does                                                   |
| ----------- | -------------------------------------------------------------- |
| `noop`      | Emits events without calling a model; for testing the pipeline |
| `echo_llm`  | Sends the input to an LLM and streams the answer               |
| `rag_chat`  | Answers from a document collection and cites sources           |
| `mcp_tools` | Calls configured remote MCP tools in a bounded loop            |

Run an agent two ways:

| Mode           | Call                                                                                             | Use for                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Streaming      | `POST /api/ai/agents/<agentId>/stream` (session route) → backend `/agents/stream`                | Interactive answers, as Server-Sent Events: `step`, `token`, `tool_call`, `tool_result`, `citation`, `final`, `error` |
| Background job | `trpc.aiJobs.create({ agentId, input })`, then `aiJobs.status`, `aiJobs.events`, `aiJobs.cancel` | Long runs; progress is stored in `AiJobRun` and `AiJobEvent`                                                          |

Ingest documents into a RAG collection with `aiJobs.create({ agentId: "rag_ingest", input })`, which queues an ingestion job. Documents are split, embedded (`RAG_EMBEDDER`, default `openai:text-embedding-3-small`) and stored in `AiDocumentChunk` with pgvector, or in Qdrant with `RAG_VECTOR_STORE=qdrant`.

The module ships the API and the pipeline, not a user interface. Build screens for your use case on these calls.

## Adding an agent

1. Create `apps/backend/src/saas_forge_backend/agents/my_agent.py` with `async def run(input_payload, ctx)` that yields `AgentEvent`s.
2. Register it in `register_default_agents()` in `agents/registry.py`.
3. Add a test in `apps/backend/tests/`.
4. Call it from the web app with its ID.

To add an LLM provider, extend `llm/factory.py`, add its credential to `config.py` and `.env.example`, and list the variable in `turbo.json` `globalEnv`.

## Backend environment

| Variable                                                                       | Description                                                                                  |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `APP_ENV`                                                                      | `production` makes the service refuse placeholder or short secrets and implicit service URLs |
| `BACKEND_DATABASE_URL`                                                         | `postgresql+asyncpg://…`                                                                     |
| `BACKEND_HMAC_SECRET`                                                          | Same value as the web app                                                                    |
| `BACKEND_HMAC_SECRET_NEXT`                                                     | Optional second secret for zero-downtime rotation                                            |
| `RAG_VECTOR_STORE`                                                             | `pgvector` (default) or `qdrant` (with `QDRANT_URL`, `QDRANT_API_KEY`)                       |
| `RAG_EMBEDDER`                                                                 | `provider:model`, default `openai:text-embedding-3-small`                                    |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, `OLLAMA_BASE_URL` | LLM providers                                                                                |
| `LOG_LEVEL`, `LOG_FORMAT`                                                      | `INFO`; `pretty` or `json`                                                                   |
| `METRICS_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT`                               | Prometheus metrics and OpenTelemetry tracing                                                 |

## Testing

```bash
cd apps/backend
uv run pytest                     # unit tests with mocks
uv run ruff check src tests       # lint
uv run pyright                    # types
```

Integration tests need the Compose services: set `BACKEND_INTEGRATION=1` with real `BACKEND_DATABASE_URL` and `BACKEND_HMAC_SECRET`, then run `uv run pytest tests/integration`.

## Deployment

`Dockerfile.backend` builds the `api` target. Deploy the API and the web Inngest functions, on a private network the web app can reach (Fly.io, Railway, Render, Kubernetes, or a Docker host with `docker-compose.backend.yml`). Set `BACKEND_URL` in the web app to the API's private address, and use `APP_ENV=production`.
