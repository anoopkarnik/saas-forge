# Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A core, CMS-backed Blog (admin editor, public pages, mobile/desktop readers) with SEO, GEO and AIO plumbing, shipped to every buyer with sample posts only.

**Architecture:** Mirror Documentation layer by layer: `BlogPost` in `cms.prisma`, MDX files + registry seeded into Postgres, `lib/functions/fetchBlog*` dispatching on `NEXT_PUBLIC_CMS`, a `blog` tRPC router with Redis-cached index. Public article pages are server components that call the lib directly so the article, metadata and JSON-LD are in the first HTML response. Pure builders in `apps/web/lib/blog/` produce JSON-LD, RSS, `llms.txt` and markdown so they are unit-testable.

**Tech Stack:** Next.js App Router, tRPC, Prisma, Upstash Redis, react-markdown, next-intl, Expo Router, Electron + react-router.

**Spec:** `docs/superpowers/specs/2026-10-27-blog-design.md`

## Global Constraints

- Blog is core: no scaffold module, no manifest, no `scaffold:begin blog` markers.
- Audit emits inside `audit_log` markers; AI fill UI and the `blog.assistant` seed inside `ai` markers (copy the doc editor / `documentation.assistant` placement exactly).
- Drafts (`status: "draft"`) never appear publicly: index, article, sitemap, RSS, `llms.txt`, markdown endpoint, mobile and desktop readers.
- Do not create a migration file; the owner runs `pnpm migrate`. Schema change is additive.
- Admin writes `adminProcedure`, admin reads `guestReadableAdminProcedure`, editing Postgres-only (`PRECONDITION_FAILED` under `constant`), as `docProcedures.ts`.
- Files with template overrides change in both places: `apps/web/trpc/routers/_app.ts`, `apps/web/trpc/apiRegistry.ts`, `apps/web/components/home/AppSidebar.tsx` and their copies in `template-overrides/saas-boilerplate/`.
- New UI strings in `packages/i18n` en + es; `pnpm i18n:check` stays green.
- **Owner preference: no per-task commits.** Everything lands as one new commit on `main` in Task 9 (local, not pushed). The spec file and this plan go in that commit.
- Root-only SaaS Forge post files live in `packages/database/src/blog/saas-forge/`; buyers get only `packages/database/src/blog/samples/`.

## Review Focus

1. A post title, excerpt or tag containing `</script>`, `<`, `&` or quotes: JSON-LD must not break out of its `<script>` and RSS must stay valid XML → Task 3 (`JsonLd` escaping test) and Task 4 (`buildRssXml` escaping test).
2. An admin unpublishes a post that was live: it must vanish from index, article (404), sitemap, RSS and `llms.txt` on the next request, which requires the Redis cache to be cleared on every write → Task 2 (`updatePost clears the blog cache`).
3. A slug with spaces, capitals or `/` typed in the admin: rejected server-side, not turned into a broken URL → Task 2 (`rejects malformed slugs`).
4. Publishing a draft that has no `publishedAt`: it gets "now", and re-saving a published post keeps its original date → Task 2 (`sets publishedAt on first publish`, `keeps publishedAt on later updates`).
5. `NEXT_PUBLIC_CMS=constant` with a registry entry marked draft, or whose MDX file is missing: hidden or 404, never a crash of the index/sitemap → Task 2 (`fetchBlogIndexFromLocal hides drafts`, `fetchBlogPostFromLocal returns null for missing file`).
