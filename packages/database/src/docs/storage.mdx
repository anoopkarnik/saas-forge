Uploaded images (profile avatars and CMS images) are stored in Vercel Blob or Cloudflare R2, chosen with `NEXT_PUBLIC_IMAGE_STORAGE`. A download keeps only the provider you chose.

## How uploads work

| Route | Who | Limit | Stored under |
| --- | --- | --- | --- |
| `POST /api/settings/modifyAvatar` | Any signed-in user (not guests) | 5 MB | `profile-images/` |
| `POST /api/cms/upload` | Admins | 10 MB | `cms-images/` |

Both routes are rate-limited and size-limited by the route policy. `apps/web/server/uploads/image-upload.ts` then:

1. checks the size,
2. reads the image with `sharp` and accepts only PNG, JPEG and WebP (the real format, not the file extension),
3. re-encodes it, which also strips metadata and applies the EXIF rotation,
4. uploads it under a random key (`<prefix>/<timestamp>-<uuid>.<ext>`) and returns the public URL.

## Option 1: Vercel Blob (default)

1. In the Vercel dashboard, open **Storage → Create → Blob** and connect the store to your project.
2. Copy the token from the store's `.env.local` tab:

```env
NEXT_PUBLIC_IMAGE_STORAGE="vercel_blob"
BLOB_READ_WRITE_TOKEN="vercel_blob_rw_..."
```

## Option 2: Cloudflare R2

1. In the Cloudflare dashboard, open **R2** and create a bucket.
2. Make it readable: connect a custom domain to the bucket, or enable the `r2.dev` public URL.
3. Under **Manage R2 API Tokens**, create a token with **Object Read & Write** on the bucket. Copy the access key ID and secret.

```env
NEXT_PUBLIC_IMAGE_STORAGE="cloudflare_r2"
R2_ACCOUNT_ID="..."
R2_ACCESS_KEY_ID="..."
R2_SECRET_ACCESS_KEY="..."
R2_BUCKET_NAME="acme-uploads"
NEXT_PUBLIC_R2_PUBLIC_URL="https://files.acme.com"
```

Without `NEXT_PUBLIC_R2_PUBLIC_URL` the returned URL points at the bucket's S3 endpoint, which is not public. Set it.

`pnpm doctor` writes and deletes a probe file to prove the credentials work, for either provider.

## Allow your image host in Next.js

Logos, hero and feature images are rendered with `next/image`, which only loads remote hosts listed in `images.remotePatterns` in `apps/web/next.config.mjs`. Add your storage host before uploading CMS images:

```js
images: {
  remotePatterns: [
    // ...existing entries
    { protocol: "https", hostname: "*.public.blob.vercel-storage.com" }, // Vercel Blob
    { protocol: "https", hostname: "files.acme.com" },                   // R2 custom domain
  ],
},
```

## Uploading from your own feature

Reuse the helpers in a session route:

```ts
import { guardRoute } from "@/server/routeGuard";
import { normalizeImageUpload, uploadNormalizedImage } from "@/server/uploads/image-upload";

export async function POST(req: Request) {
  const guard = await guardRoute(req, "/api/reports/cover");
  if (!guard.ok) return Response.json({ error: guard.error }, { status: guard.status });

  const file = (await req.formData()).get("file") as File | null;
  if (!file) return Response.json({ error: "No file provided" }, { status: 400 });

  const image = await normalizeImageUpload({ file, maxSizeBytes: 5 * 1024 * 1024 });
  const url = await uploadNormalizedImage({ ...image, keyPrefix: "report-covers" });
  return Response.json({ url });
}
```

Add the route to `apps/web/lib/route-policy.ts` with `input: "image-upload"` and a `maxBodyBytes` limit. For other file types (PDFs, video), write a separate helper; the image helper rejects anything that is not an image.
